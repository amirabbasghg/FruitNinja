۲-۱ سطوح انتزاع در کامپیوتر 1.22

پیش از تعریف سیستم‌عامل، باید جایگاه آن در معماری چندلایه‌ای کامپیوتر را درک کنیم. یک سیستم کامپیوتری مدرن از چند لایه‌ی انتزاعی (Abstraction Layer) تشکیل شده است که هر لایه، لایه‌ی زیرین خود را پوشش می‌دهد و به لایه بالایی سرویس ساده‌تری ارائه می‌کند.

از پایین به بالا حرکت می‌کنیم: افزاره‌ها (Device) به مدار (Circuit) متصل‌اند، مدارها طراحی دیجیتال را می‌سازند، طراحی دیجیتال به میکرومعماری تبدیل می‌شود، میکرومعماری ISA (مجموعه دستورالعمل‌ها) را پیاده می‌کند. سیستم‌عامل نزدیک‌ترین لایه نرم‌افزاری به ISA است — یعنی OS مستقیماً روی سخت‌افزار می‌نشیند و سرویس‌های سطح بالاتر را به کامپایلرها و برنامه‌های کاربردی ارائه می‌دهد.

چرا از انتزاع (Abstraction) استفاده می‌کنیم؟

اگر هر برنامه‌نویس مجبور بود برای نوشتن یک برنامه، مستقیماً با ترانزیستورها، مدارها یا حتی ثبات‌های CPU کار کند، توسعه نرم‌افزار عملاً غیرممکن می‌شد. انتزاع به این معناست که هر لایه، پیچیدگی لایه‌ی زیرین خود را پنهان می‌کند و تنها یک «رابط ساده‌شده» ارائه می‌دهد. مثلاً برنامه‌نویس وقتی printf("Hello") می‌نویسد، نیازی ندارد بداند چه ثبات‌هایی در CPU تغییر می‌کنند یا کدام قطعه روی دیسک می‌چرخد.

۲-۲ تعریف و اهداف سیستم‌عامل 1.23–1.31

تعریف شهودی

تصور کنید یک کاربر می‌خواهد یک برنامه را اجرا کند، فایلی را روی دیسک ذخیره کند، تصویری را چاپ کند و هم‌زمان به موسیقی گوش دهد. اگر سخت‌افزار تنها توسط خود برنامه‌ها مدیریت می‌شد، هر برنامه باید می‌دانست چطور با دیسک، چاپگر، کارت صدا و سایر برنامه‌ها هم‌کاری کند — این یعنی آشوب. سیستم‌عامل برنامۀ میانجی‌ای است که این مدیریت را به‌عهده می‌گیرد.

سیستم‌عامل (Operating System — OS)
برنامه‌ای که به‌عنوان میانجی بین کاربر (یا برنامه‌های کاربردی) و سخت‌افزار کامپیوتر عمل می‌کند. سیستم‌عامل نقش یک مدیر (Governor) را بازی می‌کند: تصمیم می‌گیرد چه زمانی، کدام برنامه به کدام منبع سخت‌افزاری دسترسی داشته باشد، تا هم عدالت بین برنامه‌ها رعایت شود و هم کارایی سیستم حفظ گردد.

چهار هدف اصلی سیستم‌عامل

سیلبرشاتز در اسلاید ۱.۲۳ چهار هدف بنیادین را برای OS برمی‌شمارد:

🎯 ۱. اجرای برنامه‌های کاربر

Execute user programs and make solving user problems easier — OS باید محیطی فراهم کند که برنامه‌های کاربر بتوانند اجرا شوند و حل مسئله برای کاربر آسان‌تر شود.

🎯 ۲. آسانی استفاده

Make computer system convenient to use — رابط کاربری، ابزار فایل، دستورات و سرویس‌ها باید ساده و قابل فهم باشند.

🎯 ۳. کارایی سخت‌افزار

Use computer HW in an efficient manner — استفاده بهینه از CPU، حافظه، دیسک و I/O، به‌گونه‌ای که منابع بیکار نمانند.

🎯 ۴. اجرای هم‌زمان چند برنامه

Allow multiple programs to simultaneously be executed in a shared HW — امکان اجرای هم‌زمان چند برنامه روی یک سخت‌افزار مشترک.

⚠️ تناقض ذاتی اهداف

دقت کنید که هدف «آسانی استفاده» گاهی با هدف «کارایی» در تضاد است. مثلاً یک رابط گرافیکی زیبا (GUI) کاربر را خوشحال می‌کند اما CPU و حافظه را مصرف می‌کند. طراحی OS همیشه یک مصالحه (Trade-off) بین این اهداف است.

آیا سیستم‌عامل الزامی است؟ 1.24

سؤال مهم: آیا یک کامپیوتر بدون سیستم‌عامل می‌تواند کار کند؟ پاسخ: بله. اولین کامپیوترها (مانند ENIAC) سیستم‌عامل نداشتند. در آن دوران:

  • کامپیوتر در هر لحظه فقط یک برنامه اجرا می‌کرد.
  • امکان اجرای هم‌زمان دو کار (مثلاً باز کردن یک سند و در عین حال نگه‌داشتن ساعت روی صفحه) وجود نداشت.
  • هر برنامه باید خودش کارهای فراوانی را انجام می‌داد: بارگذاری خود، دسترسی به I/O، مدیریت خطاها و غیره.

این محدودیت‌ها انگیزهٔ اصلی پیدایش سیستم‌عامل بودند: «بیاییم کارهای مشترک همه برنامه‌ها (مانند کنترل I/O، تخصیص حافظه، زمان‌بندی CPU) را در یک برنامهٔ مرکزی جمع کنیم.»

📖 مفهوم Stored Program

یادآوری از معماری فون‌نویمان: برنامه‌ها به‌صورت داده روی حافظه ذخیره می‌شوند و CPU آن‌ها را یکی‌یکی fetch و اجرا می‌کند. اما برای fetch اولین دستور، CPU باید بداند از کدام آدرس شروع کند — و این آدرس در یک حافظه-only-read (ROM) از پیش تعیین شده است.

برنامه بوت‌استرپ (Bootstrap Program)
برنامه‌ی کوچکی که در زمان روشن‌شدن یا Restart بارگذاری می‌شود. این برنامه معمولاً در ROM یا EPROM ذخیره شده و به‌طور کلی به آن Firmware می‌گویند. وظایف بوت‌استرپ:
  1. مقداردهی اولیه همه جنبه‌های سیستم (ثبات‌های CPU، کنترل‌کننده‌های دستگاه).
  2. بارگذاری Kernel سیستم‌عامل از دیسک به RAM.
  3. آغاز اجرای Kernel.
  4. Kernel سپس اولین فرایند (مانند init در Linux) را آغاز می‌کند.

۲-۵ کنترل‌کننده مدیریت پایه‌برد (BMC) و مقداردهی BIOS 1.36–1.39

BMC چیست؟

کنترل‌کننده مدیریت پایه‌برد (Baseboard Management Controller — BMC)
یک کامپیوتر کوچک (معمولاً مبتنی بر ARM SoC) که روی مادربرد هر سرور قرار دارد. BMC مستقل از CPU اصلی و سیستم‌عامل اصلی عمل می‌کند و یک رابط گرافیکی (GUI) همراه منطق داخلی برای مدیریت از راه دور دارد. با استفاده از BMC می‌توان سرور را حتی اگر OS هنگ کرده باشد، از راه دور مدیریت، ری‌استارت یا عیب‌یابی کرد.
📖 چرا BMC مهم است؟

در دیتاسنترها، مدیر سیستم نمی‌تواند به‌طور فیزیکی به هر سرور دسترسی داشته باشد. اگر کرنل Linux هنگ کند، مدیر از طریق BMC (که از کارت شبکه اختصاصی خود استفاده می‌کند) می‌تواند سرور را ری‌استارت دهد، دمای CPU را ببیند، یا حتی کنسول سریال را از راه دور ببیند. نمونه‌های شناخته‌شده: IPMI, Dell iDRAC, HP iLO, Supermicro IPMI.

از BIOS تا راه‌اندازی OS

روند کامل از فشار دادن دکمه Power تا اجرای OS به این ترتیب است 1.38:

  1. Power-On: منبع تغذیه پایدار می‌شود.
  2. BMC آماده می‌شود: سنسورها، فن‌ها و ولتاژها چک می‌شوند.
  3. BIOS/UEFI اجرا می‌شود: POST (Power-On Self Test) انجام می‌شود؛ حافظه و دستگاه‌ها چک می‌شوند.
  4. انتخاب دستگاه بوت: BIOS طبق ترتیب بوت، اولین دستگاه بوت‌شونده را پیدا می‌کند.
  5. بارگذاری Boot Sector: سکتور صفر دیسک (شامل Bootloader کوچک) به RAM خوانده می‌شود.
  6. اجرای Bootloader: Bootloader کامل (مانند GRUB) بارگذاری می‌شود و منوی انتخاب OS را نمایش می‌دهد.
  7. بارگذاری Kernel: Bootloader، فایل Kernel را از سیستم فایل به RAM می‌خواند.
  8. اجرای Kernel: کرنل مقداردهی اولیه می‌کند (درایورها، سیستم فایل، شبکه).
  9. اجرای init: اولین فرایند کاربر اجرا می‌شود و سیستم آماده می‌گردد.

  • سیستم‌عامل را با تعریف دقیق و بدون ابهام توضیح دهد و تفاوت آن با سخت‌افزار و برنامه‌های کاربردی را بشناسد.
  • چهار هدف اصلی OS را برشمارد و تناقض‌های میان آن‌ها را تحلیل کند.
  • تفاوت نگاه کاربر و نگاه سیستم به OS را بیان کند.
  • تعریف Kernel و تفاوت آن با برنامه‌های سیستمی و کاربردی را بداند.
  • روند بوت کامپیوتر را مرحله‌به‌مرحله شرح دهد و نقش ROM، BIOS، Bootloader، Kernel و init را توضیح دهد.
  • نقش BMC در سرورها را بداند.

۳ فصل سوم: ساختار سیستم کامپیوتری

در این فصل می‌آموزیم: یک سیستم کامپیوتری از چه اجزای سخت‌افزاری تشکیل شده، CPU و دستگاه‌های I/O چگونه از طریق گذرگاه (Bus) با حافظه ارتباط برقرار می‌کنند، مکانیزم وقفه (Interrupt) چیست و چرا قلب OS مبتنی بر وقفه است، درایور دستگاه چه نقشی دارد، سلسله‌مراتب حافظه و کش چگونه کار می‌کنند، DMA چگونه انتقال داده را بدون دخالت CPU انجام می‌دهد و معماری چندپردازنده (SMP, Multicore) چه تفاوتی با تک‌پردازنده دارد. 1.39–1.56

کنترل‌کننده دستگاه (Device Controller) چیست؟

هر نوع دستگاه I/O (دیسک، صدا، شبکه، USB) یک کنترل‌کننده اختصاصی دارد. کنترل‌کننده:

  • مسئول نوع خاصی از دستگاه است (مثلاً کنترل‌کننده دیسک، کنترل‌کننده صدا).
  • یک حافظه محلی (Local Buffer) دارد — داده‌ها ابتدا در اینجا قرار می‌گیرند.
  • عملیات I/O را به‌صورت مستقل از CPU انجام می‌دهد.
  • پس از پایان عملیات، با صدور یک وقفه (Interrupt) به CPU اطلاع می‌دهد.

CPU سپس داده را از Local Buffer کنترل‌کننده به حافظه اصلی منتقل می‌کند. 1.41

💡 مثال آموزشی — خواندن یک فایل از دیسک

فرض کنید کاربر روی «Open» در Word کلیک می‌کند:

  1. Word از OS می‌خواهد فایل report.doc را از دیسک بخواند.
  2. OS دستور خواندن را به کنترل‌کننده دیسک می‌دهد.
  3. کنترل‌کننده دیسک به‌صورت مستقل، سرعت دیسک را می‌چرخاند و داده‌های فایل را در Local Buffer خودش می‌ریزد.
  4. در این مدت CPU آزاد است و می‌تواند فرایند دیگری را اجرا کند (این اصل چندبرنامه‌ای است).
  5. وقتی داده‌ها آماده شد، کنترل‌کننده یک وقفه به CPU می‌فرستد.
  6. CPU وقفه را می‌پذیرد، داده را از Local Buffer به RAM منتقل می‌کند و به Word تحویل می‌دهد.

۳-۲ وقفه (Interrupt) — قلب سیستم‌عامل 1.43–1.45

مسئله

CPU با سرعت بسیار بالایی (چند گیگاهرتز) دستورات را اجرا می‌کند، در حالی که دستگاه‌های I/O بسیار کندترند (دیسک چند میلی‌ثانیه، چاپگر چند ثانیه طول می‌کشد). اگر CPU مجبور بود منتظر پایان هر I/O بماند، میلیون‌ها چرخه CPU هدر می‌رفت. وقفه سازوکاری است که به CPU اجازه می‌دهد به کار دیگری بپردازد و وقتی دستگاه کارش تمام شد، به CPU «اخطار» بدهد.

وقفه (Interrupt)
سیگنالی که از سخت‌افزار یا نرم‌افزار به CPU ارسال می‌شود و نشان می‌دهد رویدادی رخ داده که نیاز به توجه فوری دارد. وقتی وقفه می‌رسد، CPU اجرای دستور جاری را متوقف می‌کند، وضعیت خود (ثبات‌ها و PC) را ذخیره می‌کند و کنترل را به یک روتین خدمت‌رسانی وقفه (Interrupt Service Routine — ISR) منتقل می‌کند. پس از پایان ISR، اجرای برنامه اصلی از همان نقطه از سر گرفته می‌شود.

بسیاری از دانشجویان «Trap» و «Exception» را مترادف می‌پندارند. درست است که هر دو وقفه نرم‌افزاری‌اند، اما در بسیاری از متون:

  • Exception: معمولاً به خطاهای ناخواسته (تقسیم بر صفر، دسترسی غیرمجاز) اشاره دارد.
  • Trap: شامل Exception می‌شود، اما همچنین درخواست عمدی برنامه برای سرویس OS (یعنی System Call) را نیز پوشش می‌دهد.

بردار وقفه (Interrupt Vector)

چگونه CPU می‌داند برای هر وقفه، کدام تابع را اجرا کند؟ پاسخ: جدولی به‌نام Interrupt Vector در حافظه وجود دارد که شامل آدرس تمام روتین‌های خدمت‌رسانی وقفه (ISR) است. وقتی وقفه‌ای با شماره k می‌رسد، CPU به آدرس موجود در خانه k این جدول پرش می‌کند. 1.43

مراحل مدیریت وقفه 1.44

  1. ذخیره وضعیت: OS حالت CPU را با ذخیره‌سازی ثبات‌ها و Program Counter (PC) حفظ می‌کند.
  2. تشخیص نوع وقفه: CPU تعیین می‌کند چه نوع وقفه‌ای رخ داده است.
  3. اجرای ISR متناظر: قطعه کد مخصوص آن نوع وقفه اجرا می‌شود و اقدام مناسب را انجام می‌دهد.
  4. بازیابی وضعیت: پس از پایان ISR، ثبات‌ها و PC بازیابی می‌شوند و دستور متوقف‌شده از سر گرفته می‌شود.

۳-۵ کش (Cache) 1.47–1.48

کش (Cache)
حافظه‌ای کوچک و سریع که اطلاعات در حال استفاده را از حافظه کندتر به حافظه سریع‌تر به‌طور موقت کپی می‌کند. کش می‌تواند در سطوح مختلف (سخت‌افزاری، OS، برنامه) پیاده‌سازی شود. مثلاً حافظه اصلی به‌عنوان کش برای حافظه ثانویه عمل می‌کند.

مکانیزم کار کش

  1. قبل از دسترسی به داده، ابتدا کش سریع‌تر بررسی می‌شود.
  2. اگر داده در کش بود (Cache Hit)، مستقیماً از کش استفاده می‌شود — بسیار سریع.
  3. اگر نبود (Cache Miss)، داده از حافظه کندتر به کش کپی می‌شود و سپس استفاده می‌گردد.
⚠️ مسئله طراحی — کش همیشه کوچک‌تر است

چون کش کوچک‌تر از حافظه‌ای است که کش می‌شود، نمی‌توان همه داده‌ها را در کش نگه داشت. تصمیم‌گیری درباره کدام داده‌ها در کش بمانند و هنگام پر شدن، کدام داده حذف شود، یک مسئله طراحی مهم است. این تصمیم‌گیری توسط Cache Replacement Policy (مانند LRU، LFU، Random) انجام می‌شود.

📖 مهاجرت داده از دیسک به ثبات 1.82

برای درک کامل کش، تصور کنید می‌خواهیم یک داده A را از دیسک به ثبات CPU بیاوریم. مسیر:

  1. داده A در دیسک است.
  2. OS آن را به حافظه اصلی (RAM) می‌آورد (I/O).
  3. سپس به کش L3، L2 و L1 منتقل می‌شود.
  4. نهایتاً به ثبات CPU بارگذاری می‌شود.

اگر A در حافظه اصلی به‌روز شده باشد، نسخه‌های قدیمی در کش‌ها و دیسک باید هماهنگ شوند — این مفهوم Cache Coherency است که در سیستم‌های چندپردازنده‌ای و توزیع‌شده حیاتی می‌شود.

۳-۶ دسترسی مستقیم به حافظه (DMA) 1.50

مسئله

بدون DMA، هر بایت انتقال I/O نیازمند دخالت CPU بود: CPU باید داده را از Local Buffer کنترل‌کننده می‌خواند و در حافظه می‌نوشت. برای دستگاه‌های پرسرعت (مانند NIC، SSD)، این کار CPU را کاملاً مشغول می‌کرد و فرایندهای دیگر متوقف می‌شدند.

دسترسی مستقیم به حافظه (Direct Memory Access — DMA)
مکانیزمی برای دستگاه‌های I/O پرسرعت که اجازه می‌دهد کنترل‌کننده دستگاه، بلوک‌های داده را مستقیماً از Local Buffer خود به حافظه اصلی منتقل کند — بدون دخالت CPU. در این حالت، CPU تنها در ابتدای انتقال تنظیمات اولیه را به DMA Controller می‌دهد و در پایان کل بلوک، یک وقفه واحد دریافت می‌کند (به‌جای یک وقفه به ازای هر بایت).

۳-۷ معماری چندپردازنده (Multiprocessor & Multicore) 1.52–1.56

چرا چندپردازنده؟

یک سیستم تک‌پردازنده، فقط در صورتی که بسیار سریع باشد می‌تواند همه کارها را انجام دهد. اما با رشد نیاز به پردازش هم‌زمان (server، هوش مصنوعی، دیتاسنتر)، چندپردازنده‌ای ضروری شد. سه مزیت اصلی: 1.52

  1. Increased Throughput: با N پردازنده، N برابر کار انجام می‌شود (البته نه کاملاً، چون سربار هماهنگی وجود دارد).
  2. Economy of Scale: یک سیستم چندپردازنده ارزان‌تر از N کامپیوتر مجزا با همان توان کلی است (منابع مشترک: تغذیه، فن، دیسک).
  3. Increased Reliability: اگر یک پردازنده خراب شود، سیستم متوقف نمی‌شود — به آن Graceful Degradation یا Fault Tolerance می‌گویند.

📖 معماری فون‌نویمن 1.51

سیلبرشاتز در اسلاید ۱.۵۱ به «A von Neumann architecture» اشاره می‌کند. در معماری فون‌نویمن، داده و دستورالعمل‌ها در همان حافظه اصلی ذخیره می‌شوند و CPU هر دو را به‌یک‌سان fetch می‌کند. این در تضاد با معماری هاروارد (Harvard) است که داده و دستورالعمل در حافظه‌های جداگانه قرار دارند. اکثر سیستم‌های امروزی ترکیبی از این دو هستند.

پس از مطالعه این فصل، دانشجو باید بتواند:
  • مدل کلی سیستم کامپیوتری (CPU، Bus، Device Controller، حافظه) را رسم کند.
  • تفاوت وقفه سخت‌افزاری و نرم‌افزاری (Trap/Exception) را شرح دهد.
  • مراحل مدیریت وقفه (ذخیره، تشخیص، ISR، بازیابی) را به‌ترتیب بیان کند.
  • نقش Interrupt Vector و درایور دستگاه را توضیح دهد.
  • سلسله‌مراتب حافظه (ثبات، کش، RAM، SSD، HDD، نوار) را با ترتیب سرعت و ظرفیت برشمارد.
  • مکانیزم کش (Hit/Miss) و اهمیت Replacement Policy را شرح دهد.
  • DMA را توضیح دهد و تفاوت انتقال با/بدون DMA را در تعداد وقفه‌ها بیان کند.

۴-۱ چندبرنامه‌ای، چندوظیفه‌ای، چندپردازنده‌ای 1.57–1.61

مسئله: چرا نمی‌توان یک برنامه را تا آخر اجرا کرد؟

تصور کنید در یک سیستم تک‌برنامه‌ای (Non-Multiprogrammed)، تنها یک برنامه در حال اجراست. این برنامه در میانه اجرا، برای خواندن از دیسک منتظر می‌ماند (چند میلی‌ثانیه). در این مدت، CPU کاملاً بیکار است؛ چون هیچ برنامه دیگری وجود ندارد که اجرا شود. این یعنی هزاران چرخه CPU هدر می‌رود.

چندبرنامه‌ای (Multiprogramming)
روشی که در آن OS چند «شغل» (Job) را در حافظه نگه می‌دارد و وقتی یکی از آن‌ها برای I/O منتظر می‌ماند، CPU را به شغل دیگری می‌سپارد. هدف Multiprogramming، بهبود کارایی سیستم (System Efficiency) از طریق نگه‌داشتن CPU مشغول است. در این حالت، کاربر با سیستم تعامل مستقیم ندارد (Batch System).

Job Pool: مجموعه‌ی همه شغل‌هایی که در انتظار اجرا هستند (روی دیسک یا حافظه). فقط یک زیرمجموعه از کل شغل‌ها در حافظه نگه داشته می‌شود. 1.57

چندوظیفه‌ای (Multitasking / Time-Sharing) 1.58

چندوظیفه‌ای (Multitasking / Time-Sharing)
توسعه منطقی Multiprogramming که در آن CPU آن‌قدر سریع میان شغل‌ها جابه‌جا می‌شود که کاربر می‌تواند با هر شغل تعامل مستقیم داشته باشد. در Multitasking، زمان پاسخ (Response Time) باید کمتر از ۱ ثانیه باشد، تا هر کاربر این توهم را داشته باشد که کل کامپیوتر فقط در اختیار اوست. ⚠️ اشتباه رایج

بسیاری از دانشجویان Multiprogramming و Multitasking را یکی می‌پندارند. تفاوت کلیدی:

  • Multiprogramming: هدف = کارایی (CPU نباید بیکار بماند). تعامل کاربر وجود ندارد (Batch).
  • Multitasking: هدف = تعامل کاربر (Response Time کوتاه). کاربری این توهم را دارد که کامپیوتر فقط مال اوست.

در واقع، Multitasking یک «افزونه منطقی» روی Multiprogramming است — یعنی همهٔ ابزارهای Multiprogramming را دارد، اما با سرعت جابه‌جایی بسیار بیشتر.

تعریف «فرایند» در Multitasking 1.59

فرایند (Process)
یک برنامه بارگذاری‌شده در حافظه و در حال اجرا. فرایند برای مدت کوتاهی اجرا می‌شود، سپس یا پایان می‌یابد یا نیاز به I/O پیدا می‌کند. در Multitasking، چند فرایند هم‌زمان در حافظه نگه داشته می‌شوند و CPU به‌سرعت میان آن‌ها جابه‌جا می‌شود.

دو مفهوم مهم که در فصل ۵ و فصل‌های بعدی به‌طور عمیق بررسی می‌شوند:

  • Job Scheduling: تصمیم می‌گیرد کدام شغل از دیسک به حافظه آورده شود (جلسه ۶).
  • CPU Scheduling: تصمیم می‌گیرد کدام فرایند در حافظه، روی CPU اجرا شود (جلسه ۵).

Swapping و Virtual Memory 1.60

اگر فرایندها در حافظه جا نمی‌شوند چه می‌شود؟

  • Swapping: OS فرایندها را به‌طور کامل از حافظه به دیسک و برعکس جابه‌جا می‌کند.
  • Virtual Memory: اجازه می‌دهد فرایندی که کاملاً در حافظه نیست اجرا شود — حافظه منطقی (از دید کاربر) را از حافظه فیزیکی جدا می‌کند.

۴-۲ سیستم‌عامل مبتنی بر وقفه (Interrupt-Driven OS) 1.63–1.65

OS مدرن اساساً «منتظر» می‌ماند تا اتفاقی بیفتد و سپس واکنش نشان می‌دهد. اگر هیچ فرایندی برای اجرا، هیچ دستگاه I/O برای سرویس و هیچ کاربری برای پاسخ‌گویی نباشد، OS بیکار می‌نشیند و منتظر یک وقفه می‌ماند. به همین دلیل می‌گوییم OS Interrupt-Driven است. 1.63

دو منبع وقفه برای OS: 1.64–1.65

  1. وقفه سخت‌افزاری: از دستگاه‌ها (دیسک، NIC، چاپگر) یا تایمر.
  2. وقفه نرم‌افزاری (Trap/Exception):
    • خطای نرم‌افزاری: تقسیم بر صفر، دسترسی نامعتبر به حافظه، دسترسی به فضای آدرس Kernel.
    • درخواست سرویس از OS (System Call).
    • مشکلات فرایند: حلقه بی‌نهایت، فرایندهایی که به یکدیگر یا OS آسیب می‌زنند.

۴-۳ حالت دوگانه (Dual-Mode Operation) 1.66–1.71

مسئله: چگونه OS خود را محافظت کند؟

تصور کنید چند فرایند هم‌زمان در حال اجرا هستند. اگر هر فرایند بتواند مستقیماً به هر منبع سخت‌افزاری دسترسی داشته باشد، یک فرایند مخرب یا دارای خطا می‌تواند:

  • داده فرایند دیگر را بازنویسی کند.
  • دستگاه I/O را مستقیماً کنترل کند و باعث تداخل شود.
  • حافظه OS را پاک کند.
  • تایمر را غیرفعال کند و CPU را برای همیشه در اختیار بگیرد.

برای جلوگیری از این، OS باید بتواند برخی دستورات را «ممنوع» کند برای برنامه‌های کاربر. این‌ها دستورات ممتاز (Privileged Instructions) نامیده می‌شوند.

حالت دوگانه (Dual-Mode Operation)
مکانیزمی که به OS اجازه می‌دهد خود و سایر اجزای سیستم را از کاربران خطاکار محافظت کند. در این حالت، CPU در یکی از دو حالت اجرا می‌کند:
  • User Mode (حالت کاربر): دسترسی محدود به سخت‌افزار — دستورات ممتاز قابل اجرا نیستند.
  • Kernel Mode (حالت هسته): به‌هم چنین Supervisor، System یا Privileged Mode نیز می‌گویند. دسترسی کامل به سخت‌افزار — تمام دستورات قابل اجرا.

بیت حالت (Mode Bit) 1.66

سخت‌افزار یک بیت به‌نام Mode Bit فراهم می‌کند که نشان می‌دهد کد در حال اجرا در User Mode (۱) است یا Kernel Mode (۰). هنگام بوت، سخت‌افزار در Kernel Mode شروع می‌کند.

  3. HW Interrupt: وقفه از دستگاه (پایان I/O) یا تایمر.

دستورات ممتاز (Privileged Instructions) 1.67

برخی دستورات می‌توانند به سیستم آسیب بزنند، بنابراین به‌عنوان Privileged تعیین می‌شوند و فقط در Kernel Mode قابل اجرا هستند. اگر در User Mode اجرا شوند، CPU آن‌ها را به‌عنوان illegal تلقی کرده و یک trap به OS ایجاد می‌کند. نمونه‌ها:

Switching to kernel mode I/O control Setting the timer Interrupt management Clearing memory Remove process from memory
⚠️ سؤال ظریف از اسلاید ۱.۶۹

سیلبرشاتز دو سؤال کلیدی مطرح می‌کند:

  1. آیا دستور System Call برای رفتن به Kernel Mode، دستور ممتاز است یا غیرممتاز؟
  2. آیا دستور مستقیم برای رفتن به Kernel Mode، ممتاز است یا غیرممتاز؟

پاسخ کلیدی:

  • System Call: یک دستور غیرممتاز است — هر برنامه‌ای می‌تواند آن را صدا بزند. اما خود دستور System Call، به‌صورت کنترل‌شده به Kernel Mode منتقل می‌کند و کنترل به آدرس ازپیشتعیین‌شده‌ای در Kernel می‌رود. این یعنی برنامه نمی‌تواند خودسرانه هر کدی در Kernel Mode اجرا کند؛ فقط کدی که Kernel از قبل تعریف کرده.
  • دستور مستقیم برای تغییر به Kernel Mode: اگر چنین دستوری وجود داشته باشد (که نباید باشد)، ممتاز است — زیرا اگر هر برنامه‌ای بتواند مستقیماً به Kernel Mode برود، هیچ حفاظتی باقی نمی‌ماند.

این تمایز، اساس امنیت OS است.

عواقب نبود حالت دوگانه 1.70

اگر سخت‌افزار بیت حالت نداشته باشد (مانند MS-DOS روی 8088):

  • برنامه کاربر می‌تواند کل OS را پاک کند.
  • چند برنامه می‌توانند هم‌زمان به یک دستگاه بنویسند.

امروزه اکثر CPUها و OSها از Dual-Mode پشتیبانی می‌کنند (Linux, Unix, Solaris, Win-XP/Vista). برخی CPUها حتی از Multi-Mode پشتیبانی می‌کنند — مثلاً VMM (Virtual Machine Manager) Mode برای ماشین‌های مجازی مهمان.

۴-۴ System Call — جاده کاربر به Kernel 1.68

وقتی برنامه کاربر به سرویسی از OS نیاز دارد (مانند خواندن فایل، ایجاد فرایند، ارسال شبکه)، نمی‌تواند مستقیماً دستور ممتاز اجرا کند. در عوض، یک System Call صدا می‌زند.

روند اجرای System Call 1.68

  1. System Call به‌عنوان SW Interrupt اجرا می‌شود. برنامه دستور خاصی (مثل int 0x80 در x86 یا syscall در x86-64) را اجرا می‌کند.
  2. کنترل از طریق Interrupt Vector به یک روتین خدمت‌رسانی در OS منتقل می‌شود.
  3. Mode Bit به ۰ (Kernel) تغییر می‌کند.
  4. Kernel دستور interrupt کننده را بررسی می‌کند تا نوع interrupt را تعیین کند.
  5. اطلاعات اضافی ممکن است در ثبات‌ها یا پشته یافت شود (پارامترهای System Call).
  6. Kernel پارامترها را راستی‌آزمایی می‌کند (مثلاً آیا اشاره‌گر به حافظه مجاز است؟).
  7. System Call اجرا می‌شود.
  8. کنترل به دستور بعد از System Call بازمی‌گردد.
  9. Mode Bit به ۱ (User) بازمی‌گردد.
💡 مثال آموزشی — صدا زدن read()

یک برنامه C می‌خواهد از فایل بخواند:

char buf[100];
int fd = open("test.txt", O_RDONLY);
int n = read(fd, buf, 100);

هنگام اجرای read:

  1. کتابخانه C (libc) تابع wrapper را فراخوانی می‌کند که ثبات‌ها را برای System Call شماره read تنظیم می‌کند.
  2. دستور syscall اجرا می‌شود — این یک وقفه نرم‌افزاری است.
  3. CPU به Kernel Mode منتقل می‌شود و به آدرس مشخص‌شده در Interrupt Vector پرش می‌کند.
  4. Kernel پارامترها (fd, buf, 100) را راستی‌آزمایی می‌کند: آیا fd معتبر است؟ آیا buf در فضای آدرس کاربر قرار دارد؟
  5. Kernel داده را از دیسک به buf می‌خواند.
  6. Kernel تعداد بایت‌های خوانده‌شده را در ثبات بازگشت قرار می‌دهد و به User Mode برمی‌گردد.
  7. برنامه C ادامه اجرا می‌دهد.

۴-۵ تایمر (Timer) و جلوگیری از Process Hogging 1.72–1.73

مسئله: فرایند بی‌پایان

تصور کنید یک برنامه کاربر به‌اشتباه در یک حلقه بی‌نهایت افتاده است:

while(1) { /* هیچ کاری نمی‌کند */ }

اگر OS نتواند کنترل را پس بگیرد، این فرایند برای همیشه CPU را اشغال می‌کند و هیچ فرایند دیگری اجرا نمی‌شود — حتی خود OS نمی‌تواند کار کند. به این حالت Process Hogging می‌گویند.

تایمر (Timer)
مکانیزم سخت‌افزاری که از کامپیوتر در برابر فرایندهای بی‌پایان یا فرایندهایی که منابع را اشغال می‌کنند، محافظت می‌کند. تایمر به‌گونه‌ای تنظیم می‌شود که پس از یک دوره زمانی مشخص، وقفه تولید کند. یک شمارنده وجود دارد که توسط ساعت فیزیکی کاهش می‌یابد. وقتی شمارنده به صفر برسد، یک وقفه تولید می‌شود.

مکانیزم کار تایمر

  1. OS یک مقدار اولیه به شمارنده تایمر می‌نویسد (این یک دستور ممتاز است — فقط Kernel می‌تواند آن را تنظیم کند).
  2. ساعت فیزیکی، شمارنده را در هر تیک کاهش می‌دهد.
  3. وقتی شمارنده به صفر رسید، یک وقفه سخت‌افزاری تولید می‌شود.
  4. این وقفه، CPU را از User Mode به Kernel Mode منتقل می‌کند.
  5. Kernel می‌تواند تصمیم بگیرد: به همان فرایند ادامه دهد (و تایمر را دوباره تنظیم کند) یا فرایند دیگری را اجرا کند (CPU Scheduling).
🎯 نکته امتحانی

تایمر قبل از Scheduling یک فرایند تنظیم می‌شود، تا OS بتواند کنترل را پس از مدت زمان مشخصی پس بگیرد یا برنامه‌ای که از زمان اختصاص‌یافته فراتر می‌رود را خاتمه دهد. این تضمین می‌کند که هیچ فرایندی نمی‌تواند CPU را برای همیشه در اختیار بگیرد.

📖 چرا تنظیم تایمر یک دستور ممتاز است؟

اگر هر برنامه کاربر بتوانست تایمر را تنظیم کند، می‌توانست تایمر را غیرفعال کند یا آن‌قدر بزرگ تنظیم کند که خودش برای همیشه CPU را در اختیار داشته باشد. به همین دلیل، تنظیم تایمر فقط در Kernel Mode مجاز است.

۵-۱ مدیریت فرایند (Process Management) 1.74–1.76

تعریف فرایند

فرایند (Process)
یک برنامه در حال اجرا. فرایند موجودیت فعال (Active Entity) است، در حالی که برنامه موجودیت منفعل (Passive Entity) روی دیسک است. فرایند واحد کار (Unit of Work) در یک سیستم است. هر فرایند برای انجام وظیفه‌اش به منابعی نیاز دارد: CPU، حافظه، I/O، فایل‌ها، داده‌ی مقداردهی اولیه. هنگام خاتمه فرایند، منابع قابل استفاده مجدد باید پس گرفته شوند.
⚠️ تفاوت Program و Process — یک مفهوم کلیدی

این تمایز، یکی از مهم‌ترین مفاهیم درس است و در امتحان قطعاً سؤال می‌شود:

معیارProgram (برنامه)Process (فرایند)
ماهیتمنفعل (Passive)فعال (Active)
مکانروی دیسک به‌صورت فایل اجراییدر حافظه اصلی در حال اجرا
زمان حیاتتا زمان حذف فایلاز ایجاد تا خاتمه
تعدادیک فایل برنامه، یک نسخهیک برنامه می‌تواند چند فرایند هم‌زمان داشته باشد
نیاز به منابعفقط فضای دیسکCPU، حافظه، I/O، فایل‌ها

مثال: فایل firefox.exe روی دیسک، یک Program است. وقتی آن را اجرا می‌کنید، یک Process ایجاد می‌شود. اگر دوباره روی آیکون کلیک کنید، یک Process دیگر از همان Program ایجاد می‌شود — دو فرایند، اما یک برنامه.

۵-۲ مدیریت حافظه (Memory Management) 1.76–1.78

چرا مدیریت حافظه مهم است؟

حافظه اصلی (RAM) مخزن داده‌های با دسترسی سریع است که بین CPU و دستگاه‌های I/O مشترک است. تنها حافظه‌ی بزرگ‌ای است که CPU می‌تواند مستقیماً آدرس‌دهی و دسترسی کند. 1.76

برای اجرای یک برنامه:

  • تمام (یا بخشی از) دستورالعمل‌های آن باید در حافظه باشند.
  • تمام (یا بخشی از) داده‌های مورد نیاز باید در حافظه باشند.

و برای بهبود بهره‌وری CPU:

  • چند برنامه باید هم‌زمان در حافظه نگه داشته شوند — این نیازمند مدیریت حافظه است.

فعالیت‌های مدیریت حافظه 1.77

مدیریت حافظه تعیین می‌کند چه چیزی در حافظه است و کِی. هدف: بهینه‌سازی بهره‌وری CPU و پاسخ به کاربر. فعالیت‌ها:

  1. Tracking: پیگیری اینکه کدام بخش‌های حافظه در حال حاضر استفاده می‌شوند و توسط چه کسی.
  2. Decision: تصمیم‌گیری درباره اینکه کدام فرایندها (یا بخش‌هایی از آن‌ها) و چه داده‌ای به حافظه وارد یا از آن خارج شوند.
  3. Allocation: تخصیص و آزادسازی فضای حافظه بر حسب نیاز.
📖 نکته — جلسات بعدی

مباحث عمیق مدیریت حافظه در جلسات ۶-۷ درس بررسی می‌شوند: Swapping، Paging، Page Table، Segmentation، Virtual Memory و Demand Paging. این فصل صرفاً یک نگاه کلی است.

۵-۳ مدیریت ذخیره‌سازی (Storage Management) 1.78–1.80

چرا مدیریت ذخیره‌سازی مهم است؟

OS یک نمای منطقی و یکنواخت از ذخیره‌سازی اطلاعات ارائه می‌دهد — کاربر نیازی ندارد بداند داده روی HDD است یا SSD، یا کدام سکتور. OS ویژگی‌های فیزیکی را به یک واحد ذخیره‌سازی منطقی به‌نام فایل (File) انتزاع می‌کند. 1.78

چرا به ذخیره‌سازی انبوه نیاز داریم؟ 1.79

  • حافظه اصلی برای نگه‌داری تمام داده‌ها/برنامه‌ها به‌قدر کافی بزرگ نیست.
  • حافظه اصلی فرّار است — هنگام قطع برق داده از دست می‌رود.

دیسک معمولاً برای نگه‌داری داده‌ای استفاده می‌شود که در حافظه اصلی جا نمی‌شود یا باید برای مدت «طولانی» نگه داشته شود. مدیریت صحیح دیسک از اهمیت مرکزی برخوردار است — کل سرعت عملیات کامپیوتر به زیرسیستم دیسک و الگوریتم‌های آن بستگی دارد.

فعالیت‌های OS در زمینه ذخیره‌سازی 1.80

  • Free-space management: مدیریت فضای آزاد روی دیسک.
  • Storage allocation: تخصیص ذخیره‌سازی به فایل‌ها.
  • Disk scheduling: زمان‌بندی دیسک (ترتیب خدمت‌رسانی به درخواست‌های I/O).

ذخیره‌سازی ثالثیه 1.80

برخی داده‌ها نیاز به سرعت بالا ندارند — روی ذخیره‌سازی ثالثیه (دیسک نوری، نوار مغناطیسی) نگه‌داری می‌شوند. این‌ها همچنان باید توسط OS یا برنامه‌ها مدیریت شوند. انواع:

  • WORM (Write-Once, Read-Many): یک‌بارنویس، چندبارخوان (مانند CD-R).
  • RW (Read-Write): خوانا-نوشتنی (مانند CD-RW، DVD-RW).

در محیط‌های Multitasking باید مراقب بود که همیشه جدیدترین مقدار داده استفاده شود، بدون توجه به اینکه در کجای سلسله‌مراتب ذخیره شده است. سه چالش:

  • Multitasking: داده ممکن است هم‌زمان در کش و حافظه باشد — باید آخرین نسخه استفاده شود.
  • Multiprocessor: سخت‌افزار باید Cache Coherency را تضمین کند — همه CPUها باید آخرین مقدار را در کش خود ببینند.
  • Distributed: چندین نسخه از داده می‌تواند وجود داشته باشد — به هماهنگ‌سازی در سطح OS نیاز است.

بخش سوم: مرور نهایی

مرور جمع‌بندی کلی درس

این جلسه، یک «نگاه کلی از بالا» به کل درس سیستم‌عامل بود. در طول ترم، هر یک از مفاهیمی که در این‌جا معرفی شدیم، به‌طور عمیق بررسی خواهد شد. در ادامه، مهم‌ترین مفاهیم این جلسه را در یک نگاه مرور می‌کنیم:

سیستم‌عامل چیست؟

سیستم‌عامل برنامه‌ای میانجی بین کاربر/برنامه‌های کاربردی و سخت‌افزار است. تنها بخشی از OS که همیشه در حال اجراست، Kernel است. هر چیز دیگر یا برنامه سیستمی (همراه OS) یا برنامه کاربردی است.

روند بوت کامپیوتر

ROM → بوت‌استرپ (Firmware) → BIOS/UEFI → Bootloader → Kernel → اولین فرایند (init). هر مرحله، مرحله بعد را بارگذاری می‌کند.

ساختار سخت‌افزاری

CPU و کنترل‌کننده‌های دستگاه از طریق یک گذراغ مشترک به حافظه دسترسی دارند. هر کنترل‌کننده یک Local Buffer دارد و با صدور وقفه به CPU خبر می‌دهد. درایور دستگاه، رابط یکنواختی بین کنترل‌کننده و Kernel فراهم می‌کند.

وقفه (Interrupt) — قلب OS

دو نوع: سخت‌افزاری (از دستگاه‌ها) و نرم‌افزاری (Trap/Exception — خطا یا System Call). OS مدرن مبتنی بر وقفه است. مراحل مدیریت وقفه: ذخیره وضعیت → تشخیص نوع → اجرای ISR → بازیابی وضعیت.

سلسله‌مراتب حافظه

از ثبات (سریع‌ترین، کوچک‌ترین) تا نوار مغناطیسی (کندترین، بزرگ‌ترین). کش، حافظه‌ی سریع‌تری است که داده‌های در حال استفاده را موقتاً از حافظه کندتر کپی می‌کند. DMA اجازه می‌دهد دستگاه مستقیماً به حافظه منتقل کند — یک وقفه به ازای هر بلوک به‌جای هر بایت.

چندپردازنده

SMP (همه پردازنده‌ها هم‌تراز، حافظه مشترک) رواج دارد. Multicore: چند هسته در یک تراشه — از دید OS همان چند CPU است.

ساختار OS

Multiprogramming (هدف: کارایی) → Multitasking (هدف: تعامل کاربر) → Multiprocessing (چند CPU). همه این‌ها روی Multiprogramming ساخته می‌شوند.

حالت دوگانه (Dual-Mode)

User Mode (Mode Bit=1) و Kernel Mode (Mode Bit=0). سه رویداد باعث User→Kernel می‌شوند: System Call، Exception، HW Interrupt. دستورات ممتاز فقط در Kernel قابل اجرا. تایمر از Process Hogging جلوگیری می‌کند.

اجزای OS

سه جزء اصلی: Process Management (ایجاد/حذف، تعلیق، همگام‌سازی، IPC، Deadlock)، Memory Management (پیگیری، تصمیم، تخصیص) و Storage Management (فضای آزاد، تخصیص، زمان‌بندی دیسک).

بخش اول: سؤالات چهارگزینه‌ای (هر کدام ۳ نمره)

چهارگزینه‌ای ۱
کدام گزاره درباره Kernel درست است؟
  1. Kernel برنامه‌ای است که فقط هنگام بوت اجرا می‌شود.
  2. Kernel آن یک برنامه‌ای است که همیشه در حال اجراست.
  3. Kernel همان برنامه‌های سیستمی است که همراه OS ارسال می‌شوند.
  4. Kernel شامل تمام برنامه‌های کاربردی و سیستمی است.
چهارگزینه‌ای ۲
برنامه Bootstrap در کجا ذخیره می‌شود و اولین وظیفه‌اش چیست؟
  1. در HDD — بارگذاری اولین فرایند کاربر.
  2. در RAM — مقداردهی ثبات‌های CPU.
  3. در ROM/EPROM — بارگذاری Kernel از دیسک به RAM.
  4. در Cache — بارگذاری درایور دستگاه.
چهارگزینه‌ای ۳
هنگامی که یک برنامه در User Mode سعی می‌کند یک دستور ممتاز (مثل I/O Control) اجرا کند، چه اتفاقی می‌افتد؟
  1. دستور اجرا می‌شود، چون CPU همیشه در Kernel Mode است.
  2. CPU آن را illegal تلقی کرده و یک trap به OS ایجاد می‌کند.
  3. دستور اجرا می‌شود، اما با تأخیر.
  4. برنامه بلافاصله خاتمه می‌یابد بدون هیچ رویدادی.
چهارگزینه‌ای ۴
تفاوت کلیدی Multiprogramming و Multitasking چیست؟
  1. Multiprogramming چند CPU دارد، Multitasking یک CPU.
  2. Multiprogramming هدفش کارایی است، Multitasking هدفش تعامل کاربر است.
  3. Multiprogramming فقط در سرورهاست، Multitasking فقط در موبایل.
  4. تفاوتی ندارند — دو نام برای یک مفهوم.
چهارگزینه‌ای ۵
DMA باعث می‌شود تعداد وقفه‌ها به ازای انتقال N بایت چقدر باشد؟
  1. N وقفه (یک وقفه به ازای هر بایت).
  2. یک وقفه به ازای کل بلوک.
  3. هیچ وقفه‌ای — DMA کاملاً بی‌وقفه است.
  4. N/2 وقفه.
چهارگزینه‌ای ۶
کدام‌یک از موارد زیر یک System Call نیست؟
  1. read()
  2. open()
  3. fork()
  4. printf() — چاپ مستقیم به صفحه‌نمایش بدون درخواست سرویس OS
چهارگزینه‌ای ۷
در SMP (Symmetric Multiprocessing)، کدام گزاره درست است؟
  1. یک Master به Slave‌ها کار تخصیص می‌دهد.
  2. هر پردازنده فقط وظیفه خاصی انجام می‌دهد.
  3. همه پردازنده‌ها هم‌تراز (Peer) و حافظه مشترک دارند.
  4. هر پردازنده حافظه جداگانه دارد.
چهارگزینه‌ای ۸
وقتی شمارنده تایمر به صفر می‌رسد، چه اتفاقی رخ می‌دهد؟
  1. تایمر متوقف می‌شود و CPU به اجرای برنامه ادامه می‌دهد.
  2. یک وقفه سخت‌افزاری تولید می‌شود و کنترل به OS می‌رود.
  3. یک System Call از سمت کاربر اجرا می‌شود.
  4. RAM پاک می‌شود.

بخش دوم: درست/نادرست با دلیل (هر کدام ۴ نمره)

برای هر گزاره، «درست» یا «نادرست» را مشخص کنید و یک جمله دلیل بنویسید.

درست/نادرست ۹
دستور «تغییر مستقیم به Kernel Mode» یک دستور غیرممتاز است که هر برنامه کاربر می‌تواند آن را اجرا کند.
درست/نادرست ۱۰
یک Program می‌تواند به چند Process هم‌زمان تبدیل شود.
درست/نادرست ۱۱
Trap و Exception دقیقاً یک مفهوم هستند و تفاوتی ندارند.
درست/نادرست ۱۲
در Cache Miss، داده مستقیماً از کش خوانده می‌شود بدون نیاز به دسترسی به حافظه کندتر.
درست/نادرست ۱۳
تنظیم تایمر یک دستور ممتاز است.
درست/نادرست ۱۴
از دید OS، یک تراشه Multicore و یک سیستم Multi-chip چند‌پردازنده‌ای تفاوتی دارند.

بخش سوم: سؤالات تشریحی کوتاه (هر کدام ۶ نمره)

تشریحی ۱۵
چهار هدف اصلی سیستم‌عامل را برشمارد و توضیح دهید چرا این اهداف ممکن است با هم در تضاد باشند.
تشریحی ۱۶
مراحل اجرای یک System Call را (از صدا زدن تا بازگشت به User Mode) به‌ترتیب شرح دهید.
تشریحی ۱۷
سه رویدادی که باعث انتقال از User Mode به Kernel Mode می‌شوند را نام برده و برای هر کدام یک مثال بزنید.
تشریحی ۱۸
Device Controller و Device Driver را تعریف کنید و تفاوت نقش آن‌ها را شرح دهید.
تشریحی ۱۹
سلسله‌مراتب ذخیره‌سازی را از سریع‌ترین/کوچک‌ترین تا کندترین/بزرگ‌ترین به‌ترتیب بنویسید و دلیل وجود این سلسله را توضیح دهید.

بخش چهارم: تحلیل سناریو (هر کدام ۸ نمره)

سناریو ۲۰
فرض کنید کامپیوتری بدون تایمر و بدون حالت دوگانه داریم. کاربری برنامه‌ای اجرا می‌کند که در یک حلقه بی‌نهایت گرفتار شده است: while(1) { x++; }. توضیح دهید چه اتفاقی می‌افتد و چرا. سپس توضیح دهید اضافه‌شدن هر یک از مکانیزم‌های «تایمر» و «حالت دوگانه» (به‌تنهایی) چه کمکی می‌کند.
سناریو ۲۱
فرایند A در حال اجرا روی CPU است و در میانه اجرا، برای خواندن از دیسک درخواست I/O می‌دهد. فرایندهای B و C در صف Ready هستند. روند کامل رویدادها را به‌ترتیب زمانی شرح دهید: چه کسی I/O را شروع می‌کند، CPU در مدت I/O چه می‌کند، وقفه چگونه رخ می‌دهد، و چه کسی پس از پایان I/O اجرا می‌شود.

بخش پنجم: مقایسه (۶ نمره)

مقایسه ۲۲
جدول مقایسه‌ای بین «انتقال داده با DMA» و «انتقال داده بدون DMA» رسم کنید. معیارها: نقش CPU، تعداد وقفه، کارایی، پیچیدگی سخت‌افزاری.

پاسخ پاسخ‌نامه تشریحی

برای هر سؤال، پاسخ صحیح و دلیل آن آمده است. در سؤالات چهارگزینه‌ای، توضیح داده شده چرا گزینه‌های دیگر نادرست‌اند.

پاسخ سؤالات چهارگزینه‌ای

سؤال ۱ — پاسخ: (b)

پاسخ صحیح: (b) Kernel آن یک برنامه‌ای است که همیشه در حال اجراست.

دلیل: طبق تعریف سیلبرشاتز (اسلاید ۱.۳۳)، Kernel تنها برنامه‌ای است که به‌طور مداوم در حال اجراست. سایر برنامه‌ها یا سیستم‌اند (همراه OS) یا کاربردی.

چرا بقیه نادرست‌اند؟ (a) Kernel فقط هنگام بوت اجرا نمی‌شود — همیشه مقیم است. (c) برنامه‌های سیستمی جدا از Kernel‌اند. (d) Kernel شامل برنامه‌های کاربردی نیست.

سؤال ۲ — پاسخ: (c)

پاسخ صحیح: (c) در ROM/EPROM — بارگذاری Kernel از دیسک به RAM.

دلیل: طبق اسلاید ۱.۳۴، Bootstrap در ROM/EPROM (Firmware) ذخیره می‌شود و وظیفه‌اش بارگذاری Kernel از دیسک به RAM است.

چرا بقیه نادرست‌اند؟ (a) HDD فرّار در زمان خاموشی اولیه نیست ولی BIOS از ROM می‌خواند نه از HDD. (b) RAM در زمان خاموشی خالی است. (d) Cache بسیار کوچک است و نمی‌تواند درایور را نگه دارد.

سؤال ۳ — پاسخ: (b)

پاسخ صحیح: (b) CPU آن را illegal تلقی کرده و یک trap به OS ایجاد می‌کند.

دلیل: طبق اسلاید ۱.۶۷، دستورات ممتاز فقط در Kernel Mode قابل اجرا هستند. اگر در User Mode اجرا شوند، به‌عنوان illegal تلقی شده و یک trap ایجاد می‌کنند.

چرا بقیه نادرست‌اند؟ (a) و (c) امنیت OS را نقض می‌کنند. (d) برنامه بدون رویداد خاتمه نمی‌یابد — قبل از خاتمه، trap رخ می‌دهد.

سؤال ۴ — پاسخ: (b)

پاسخ صحیح: (b) Multiprogramming هدفش کارایی است، Multitasking هدفش تعامل کاربر است.

دلیل: طبق اسلایدهای ۱.۵۷-۱.۵۸، Multiprogramming یک Batch System است که CPU را مشغول نگه می‌دارد. Multitasking توسعه منطقی Multiprogramming است با سرعت جابه‌جایی بالا برای تعامل کاربر (Response Time < 1s).

چرا بقیه نادرست‌اند؟ (a) هر دو می‌توانند روی تک‌CPU یا چندCPU باشند. (c) محدود به نوع دستگاه نیستند. (d) دو مفهوم متفاوت‌اند.

سؤال ۵ — پاسخ: (b)

پاسخ صحیح: (b) یک وقفه به ازای کل بلوک.

دلیل: طبق اسلاید ۱.۵۰، با DMA فقط یک وقفه به ازای هر بلوک تولید می‌شود (نه به ازای هر بایت). این مزیت اصلی DMA است.

چرا بقیه نادرست‌اند؟ (a) حالت بدون DMA است. (c) DMA هنگام پایان بلوک وقفه می‌دهد. (d) نصف نیست — دقیقاً یک وقفه به ازای بلوک.

سؤال ۶ — پاسخ: (d)

پاسخ صحیح: (d) printf() — چاپ مستقیم به صفحه‌نمایش بدون درخواست سرویس OS.

دلیل: در واقع، printf درون خود از System Callهایی مانند write() استفاده می‌کند، اما خود تابع printf یک تابع کتابخانه‌ای C است، نه یک System Call مستقیم. در مقابل، read، open، fork همگی System Call مستقیم‌اند.

چرا بقیه نادرست‌اند؟ (a)، (b)، (c) همگی System Call مستقیم‌اند.

سؤال ۷ — پاسخ: (c)

پاسخ صحیح: (c) همه پردازنده‌ها هم‌تراز (Peer) و حافظه مشترک دارند.

دلیل: طبق اسلاید ۱.۵۳-۱.۵۴، در SMP همه پردازنده‌ها Peer هستند، هیچ Master/Slave وجود ندارد و همه از یک حافظه مشترک استفاده می‌کنند.

چرا بقیه نادرست‌اند؟ (a) و (b) ویژگی Asymmetric Multiprocessing‌اند. (d) ویژگی Distributed System است نه SMP.

سؤال ۸ — پاسخ: (b)

پاسخ صحیح: (b) یک وقفه سخت‌افزاری تولید می‌شود و کنترل به OS می‌رود.

دلیل: طبق اسلاید ۱.۷۲، وقتی شمارنده تایمر به صفر برسد، یک وقفه تولید می‌شود. این وقفه، CPU را از User Mode به Kernel Mode منتقل می‌کند و کنترل به OS می‌رسد.

چرا بقیه نادرست‌اند؟ (a) نقض هدف تایمر است. (c) System Call از کاربر می‌آید، نه از تایمر. (d) پاک‌شدن RAM نیاز به دستور ممتاز جداگانه دارد.

پاسخ سؤالات درست/نادرست

سؤال ۹ — نادرست

نادرست. دستور «تغییر مستقیم به Kernel Mode» یک دستور ممتاز است. اگر هر برنامه‌ای بتوانست مستقیماً به Kernel Mode برود، هیچ حفاظتی باقی نمی‌ماند. در عوض، System Call دستوری غیرممتاز است که به‌صورت کنترل‌شده به Kernel منتقل می‌کند (طبق اسلاید ۱.۶۹).

سؤال ۱۰ — درست

درست. یک Program (مانند firefox.exe) می‌تواند چندین بار اجرا شود و چند Process هم‌زمان ایجاد کند. هر اجرا یک Process جداگانه است، اما همگی از یک Program مشتق شده‌اند.

سؤال ۱۱ — نادرست (با توضیح)

نادرست — با توضیح. در بسیاری از متون، Trap شامل Exception (خطاهای ناخواسته) و System Call (درخواست عمدی) می‌شود، در حالی که Exception معمولاً فقط به خطاها اشاره دارد. اما در اسلاید ۱.۴۳ سیلبرشاتز این دو یکسان فرض شده‌اند. پاسخ صحیح برای امتحان: «نادرست، با این توضیح که Trap دامنه وسیع‌تری دارد و شامل System Call نیز می‌شود، در حالی که Exception معمولاً فقط به خطاها اشاره دارد.»

سؤال ۱۲ — نادرست

نادرست. Cache Miss یعنی داده در کش نبود، بنابراین باید از حافظه کندتر به کش آورده شود. درست Cache Hit است که داده مستقیماً از کش خوانده می‌شود.

سؤال ۱۳ — درست

درست. طبق اسلاید ۱.۶۷، تنظیم تایمر (Setting the Timer) یک دستور ممتاز است — فقط در Kernel Mode قابل اجراست. اگر هر برنامه‌ای بتوانست تایمر را تنظیم کند، می‌توانست آن را غیرفعال کند و CPU را برای همیشه اشغال کند.

سؤال ۱۴ — نادرست

نادرست. طبق اسلاید ۱.۵۵، از دید OS هیچ تفاوتی بین Multicore و Multi-chip نیست — هر هسته به‌عنوان یک CPU جداگانه دیده می‌شود.

پاسخ سؤالات تشریحی

سؤال ۱۵ — چهار هدف OS

چهار هدف اصلی (اسلاید ۱.۲۳):

  1. Execute user programs — اجرای برنامه‌های کاربر و آسان‌کردن حل مسئله.
  2. Convenient to use — آسانی استفاده از کامپیوتر.
  3. Efficient HW use — استفاده کارای سخت‌افزار.
  4. Multiple programs simultaneously — اجرای هم‌زمان چند برنامه.

تضاد: هدف «آسانی استفاده» گاهی با «کارایی» در تضاد است. مثلاً یک رابط گرافیکی زیبا (GUI) آسانی را بالا می‌برد اما CPU و حافظه را مصرف می‌کند و کارایی را پایین می‌آورد. به همین دلیل طراحی OS همیشه مصالحه (Trade-off) است.

سؤال ۱۶ — مراحل System Call

طبق اسلاید ۱.۶۸، مراحل به‌ترتیب:

  1. System Call به‌عنوان SW Interrupt اجرا می‌شود.
  2. کنترل از طریق Interrupt Vector به روتین خدمت‌رسانی در OS منتقل می‌شود.
  3. Mode Bit به ۰ (Kernel Mode) تغییر می‌کند.
  4. Kernel دستور interrupt کننده را بررسی می‌کند تا نوع را تعیین کند.
  5. اطلاعات اضافی از ثبات‌ها یا پشته خوانده می‌شود (پارامترها).
  6. Kernel پارامترها را راستی‌آزمایی می‌کند.
  7. System Call اجرا می‌شود.
  8. کنترل به دستور بعد از System Call بازمی‌گردد.
  9. Mode Bit به ۱ (User Mode) بازمی‌گردد.
سؤال ۱۷ — سه رویداد User→Kernel

طبق اسلاید ۱.۶۶:

  1. System Call: درخواست عمدی سرویس — مثلاً read(fd, buf, 100).
  2. Exception: خطای نرم‌افزاری — مثلاً تقسیم بر صفر، دسترسی نامعتبر به حافظه.
  3. HW Interrupt: وقفه از دستگاه — مثلاً پایان عملیات دیسک، یا تایمر.
سؤال ۱۸ — Device Controller vs Driver

Device Controller: یک قطعه سخت‌افزاری است که نوع خاصی از دستگاه را مدیریت می‌کند. دارای Local Buffer است و عملیات I/O را مستقل از CPU انجام می‌دهد. مثلاً کنترل‌کننده دیسک، کنترل‌کننده شبکه.

Device Driver: یک ماژول نرم‌افزاری در Kernel است که پیچیدگی کنترل‌کننده را از Kernel پنهان می‌کند و یک رابط یکنواخت فراهم می‌سازد. درایور از طریق وقفه از رویدادها مطلع می‌شود.

تفاوت کلیدی: Controller سخت‌افزار است، Driver نرم‌افزار است. هر دو برای یک دستگاه کار می‌کنند، اما در سطوح متفاوت — Controller با دستگاه فیزیکی، Driver با Kernel.

سؤال ۱۹ — سلسله‌مراتب ذخیره‌سازی

از سریع‌ترین/کوچک‌ترین به کندترین/بزرگ‌ترین:

  1. Registers (~1 ns)
  2. Cache (L1 ~1 ns, L2 ~10 ns, L3 ~30 ns)
  3. Main Memory / DRAM (~100 ns)
  4. SSD (~100 μs)
  5. HDD (~10 ms)
  6. Optical Disk (دیسک نوری)
  7. Magnetic Tape (نوار مغناطیسی)

دلیل: هیچ حافظه‌ای هم‌زمان «ارزان، سریع، غیرفرّار و بزرگ» نیست. به همین دلیل، از چند سطح با مزایای متفاوت استفاده می‌کنیم — داده‌های پراستفاده در سطوح سریع‌تر، داده‌های کم‌استفاده در سطوح بزرگ‌تر. کش، پلی است که این سطوح را به هم متصل می‌کند.

سؤال ۲۰ — سناریوی حلقه بی‌نهایت

بدون تایمر و بدون Dual-Mode: برنامه در حلقه بی‌نهایت گرفتار می‌شود و چون هیچ مکانیزمی وجود ندارد که CPU را پس بگیرد، این فرایند برای همیشه CPU را اشغال می‌کند. هیچ فرایند دیگری اجرا نمی‌شود، حتی خود OS نمی‌تواند کار کند — سیستم کاملاً هنگ می‌کند.

با فقط تایمر (بدون Dual-Mode): تایمر به‌طور دوره‌ای وقفه تولید می‌کند و کنترل به OS می‌رسد. OS می‌تواند فرایند دیگری را اجرا کند یا حتی فرایند بی‌نهایت را خاتمه دهد. اما چون Dual-Mode نیست، فرایند می‌تواند مستقیماً دستورات ممتاز اجرا کند — مثلاً تایمر را غیرفعال کند یا حافظه OS را پاک کند.

با فقط Dual-Mode (بدون تایمر): فرایند در User Mode است و نمی‌تواند دستورات ممتاز اجرا کند — امنیت حفظ می‌شود. اما چون تایمر نیست، اگر فرایند در حلقه بی‌نهایت گرفتار شود، OS هیچ راهی برای پس‌گرفتن کنترل ندارد — برنامه برای همیشه CPU را اشغال می‌کند. هیچ System Call یا Exception که OS را فراخوانی کند رخ نمی‌دهد.

نتیجه: هر دو مکانیزم لازم‌اند. تایمر برای پس‌گرفتن زمان‌بندی‌شده کنترل، و Dual-Mode برای امنیت و حفاظت.

سؤال ۲۱ — سناریوی I/O

رویدادها به‌ترتیب زمانی:

  1. فرایند A در حال اجرا روی CPU است. در میانه اجرا، به read() از دیسک نیاز پیدا می‌کند.
  2. A یک System Call صدا می‌زند. Mode از User به Kernel تغییر می‌کند. OS درخواست را دریافت می‌کند.
  3. OS دستور را به Device Controller دیسک می‌فرستد. Controller مستقل، سرعت دیسک را می‌چرخاند و داده را به Local Buffer خود می‌ریزد.
  4. A به حالت Waiting/Blocked می‌رود (منتظر I/O).
  5. OS یک فرایند دیگر از Ready Queue انتخاب می‌کند (CPU Scheduling) — مثلاً B را.
  6. CPU به اجرای B می‌پردازد. در این مدت، دیسک در پس‌زمینه کار می‌کند.
  7. وقتی دیسک کارش تمام شد، یک وقفه سخت‌افزانی تولید می‌کند.
  8. وقفه، CPU را از B به Kernel منتقل می‌کند. Mode از User به Kernel تغییر می‌کند.
  9. ISR اجرا می‌شود: داده از Local Buffer به RAM منتقل می‌شود و A به حالت Ready بازمی‌گردد.
  10. OS تصمیم می‌گیرد کدام فرایند بعد اجرا شود. اگر Scheduling مناسب باشد، ممکن است A ادامه دهد یا B ادامه دهد یا C شروع شود.

نکته کلیدی: در طول I/O، CPU بیکار نماند — به B پرداخت. این اصل Multiprogramming است.
